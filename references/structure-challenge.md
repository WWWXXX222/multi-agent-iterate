# 结构挑战与价值判断

用于需要整体判断的方案、文档、设计或实现。在第一轮细节评审前读取；后续仅在出现新证据、明显停滞或用户改变方向时重开。流程计入既定轮次和 agent 预算。

## 判断是否需要

适合：现稿已有很多条目却难以决策；不同性质的工作混排；目标、手段和依赖混用；用户希望主动提出关键反馈；实现方式尚未确定或证据提示当前边界造成问题。

可以跳过：结构已明确且没有冲突迹象、用户只改局部、只修具体缺陷，或已有有效的独立结构结论。记录一句理由即可，不强制增加文件。用户固定的目录、接口或范围属于约束；即使发现更好的替代，也先提出条件建议。

## 两份独立判断

1. **从原始问题拆解**：挑战者收到用户用途、原始资料、已确认决定和硬约束。先不提供可变目录、现稿解法、主控倾向及其他评审结论。要求提出能帮助判断优先级、投入、依赖或成效的组织方式，并说明取舍。用户明确要求的格式和接口不能隐藏。
2. **对现稿诊断**：另一位评审者收到相同事实和现稿，独立判断读者或用户能否完成目标，哪里混淆、遗漏或约束冲突。初次判断不读取挑战者方案。
3. **主控比较**：核对两者的证据，选择保留、局部调整或重构。必要时再开放对照材料复核。没有独立上下文时说明限制，不把同一 agent 的两次回答称为独立发现。

原始资料不可避免地包含现稿结构时如实记录；不要通过删掉关键事实制造“盲”。独立拆解只需要足够支持判断的结构和例子，不默认要求另写完整文稿或代码。

## 值得追问的方向

按任务选择少数有用问题，不逐项机械填表：

- **结果与手段**：哪一条是最终成效，哪一条是实现它的项目或使能能力？
- **分类与粒度**：目的、成熟度、责任或验证方式不同的内容，是否需要分开？细分是否真的帮助决策？
- **遗漏与替代**：哪个关键依赖、失败路径或机会没有进入框架？有没有更少步骤、更多复用或不同顺序的解法？
- **价值与投入**：哪些条目值得优先做、合并或停止？依据与机会成本是什么？
- **指标与因果**：当前数字测的是活动、产出还是效果？如何识别改变是否有用？

不同分类维度可能交叉。可以用主分类加依赖或标签表达，保留原条目到新结构的映射；工作量、成本和成果不能重复计算。不预设所有路线图都要用同一套分类，也不固定分类数量。

## 反馈要能直接用于修改

对重要建议写清：

> **发现**：具体混淆、遗漏或机会在哪里，依据是什么？
>
> **影响**：它妨碍了什么决策、用户任务或结果？
>
> **改法**：拆、并、重排或改变什么；给一个实际条目、文字或接口示例。
>
> **验证**：用什么前后对照判断收益；哪些原约束必须继续满足？

区分已证实缺陷、可验证假设与偏好。主控比较原结构和替代方案的决策价值、执行清晰度、理解成本及迁移代价。保留有效内容；不要把评审意见全部并入，也不以篇幅、类别数或“创新分数”衡量收益。

优先推进最有影响的一两个结构问题，重大遗漏和事实错误仍须处理。需要外部事实的创新思路标为条件建议，可以提出最小验证；不能把假设写成已验证的结论。没有明显收益时允许不改。
