# 使用示例

均为虚构场景，不预设企业、指标或工具。

## 已有方案，自主迭代

“用 $multi-agent-iterate 改善这份产品方案，保留现有预算与上线日期，最多两轮，尽量不要逐轮问我。”

从现稿与原始需求建立契约，明确读者要做的决定；判断是否存在层级混用、遗漏或不合理依赖。需要时由独立上下文先从原始资料拆解，另一位评审现稿，不默认生成多份平行战略。主控裁决后修订，检查约束和关键任务是否改善。未知使用量留待核；不因缺少它停下所有文稿工作。

## 路线图的结构与指标

“用 $multi-agent-iterate 改善这份年度路线图，让管理者能明确投入顺序和验收方法。”

先判断现有分类是否支撑投入决策，是否混淆结果、使能能力和前置依赖。拆分或合并的建议须给实际条目、取舍与承接关系；交叉工作只计一次。指标按结果类型选择单位，缺少基线或目标时明确待定，不统一补百分比。具体分类应从本次材料产生，不照搬别的路线图。

## 方向未定，比较候选

“用 $multi-agent-iterate 给这份复杂报告找更清晰的结构，比较两个方案后选一个。”

两个 agent 读取相同原文，各自写完整结构与理由；独立裁判按读者需要比较，主控读完选底稿。吸收另一稿一项有用安排后，重新核对全文信息和论证，不能把两个目录叠加成更长目录。

## 可拆开的技术任务

“用 $multi-agent-iterate 完成这三个互不依赖的模块，接口已确定，验证后交付。”

按模块分配写入范围，测试方法与接口契约先明确。主控整合后运行用户路径及接口回归；某一模块缺失时不报告整体完成。部署只有在当前任务包含该授权时进行，不因用这个 skill 自动增加发布阶段。

## 内容与实现一起交付

“用 $multi-agent-iterate 把这份讨论稿做成可交互网页，保留内容口径。”

分别核对讨论稿的事实、结构及阅读用途，与网页的渲染、交互和导出。内容更清楚但页面丢项，或页面正常但关键结论无依据，都需要处理；不以一侧通过代替整体验收。

## 小修改、只评审、续跑

- “把第3条移到第1条”：直接调整并验证顺序、引用和编号，无需 arena。
- “只挑这份策略的问题”：交付有证据的裁决报告，保留原稿。
- “继续上次那两轮”：读契约与检查点，核对最后一版和已完成验证，只接着未完步骤做。

专门领域已有适用 skill 时沿用其领域规则。此 skill 提供编排方法，不替代领域验收，也不同时开两套重复运行。
