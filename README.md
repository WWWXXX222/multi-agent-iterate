# Multi-Agent Iterate

让多个 agent 独立提出方案、查找问题，再由一个主控裁决、修订和验证，减少你逐轮提供 feedback 的负担。

适用于产品方案、研究报告、设计、代码实现和公司规划。它是一个负责组织协作的 skill，按任务需要调度子 agent；具体规则见 [SKILL.md](SKILL.md)。

## 快速开始

安装后，在 Codex 中附上现稿或提供文件路径，然后直接说：

```text
用 $multi-agent-iterate 改善这份方案，最多 3 轮。
保留已确认的预算、上线日期和目标范围。
自行评审、修订和验证，最后给我推荐稿、改动依据和关键待决项。
```

最好提供四项信息：**想交付什么、现有材料、不能改变的约束、迭代上限**。已有的测试或验收标准也可以一起给出；主控会先明确如何判断结果是否改善。

## 它如何工作

先确定目标、约束和验收条件，再按任务选择流程：

| 任务状态 | 采用的方法 | 示例 |
| --- | --- | --- |
| 方向未定 | **Arena：独立提案**，比较后选一个底稿，吸收兼容的优点 | 比较两种产品方案或报告结构 |
| 方向已定、工作可拆开 | **Swarm：分工执行**，划清文件或交付物边界，再整合验证 | 并行完成接口已确定的几个模块 |
| 已有稿件 | **Interrogate + 修订**，独立评审后逐项裁决和修改 | 改善策略、文稿或现有实现 |
| 只需要评审 | 独立评审后交付问题与判断 | 找出方案漏洞，保留原稿 |

每一轮完成以下循环：

**独立评审 → 主控裁决 → 修订或有理由不改 → 按相同条件验证 → 保留有效结果。**

评审者需要提供问题位置、证据和验证办法。主控读取实际产物，决定哪些意见采纳、哪些拒绝、哪些仍待核实。验收结论对应最终版本；整合或修改后，受影响的部分需要重新验证。

## 默认运行方式

| 项目 | 默认设置 |
| --- | --- |
| 候选方案 | 方向未定时，2 个独立候选 |
| 修订轮数 | 最多 3 轮，可由你指定 |
| 独立评审 | 复杂结果安排 2 个独立评审上下文 |
| 模型 | 继承当前可用模型；同模型独立上下文也可以运行 |
| 并发 | 按环境能力和任务需要安排，可分批执行 |
| 停止条件 | 达成验收、完成指定轮数、达到资源上限，或默认流程连续 2 轮无实质改善 |

你的明确要求优先于默认值。精确指定“两轮”时，会完成两轮复核，但不会为了凑轮数强行改稿。没有子 agent 能力时，会披露限制并顺序完成可做的工作。

只有会影响方向、缺少必要授权，或无法从资料和验证中解决的取舍，才需要你介入。未知事实和未经确认的指标会保留为待核项。

## 最后会得到什么

- **推荐结果**：可以直接审阅的最终稿或实现。
- **改动依据**：修复了什么，哪些建议未采纳，以及理由。
- **验证证据**：实际检查、测试或原始资料对照，说明本次能验证到哪里。
- **运行记录**：实际 agent 配置、轮次、停止原因和关键待决项；复杂任务留有检查点，便于继续。

结果会注明质量状态：`VERIFIED` 表示约定的验收已通过；`CONDITIONAL` 表示仍有外部条件或待决项；`INCOMPLETE` 表示必要工作未完成。到达轮次上限本身不代表通过。

## 其他调用示例

**比较方案**

```text
用 $multi-agent-iterate，基于这些资料独立提出两个方案，
比较后选一个，说明取舍，并验证整合后的版本。
```

**只做评审**

```text
用 $multi-agent-iterate 评审这份策略，重点检查证据和执行可行性。
只交付问题与主控裁决，先不要修改原稿。
```

**继续上次的工作**

```text
用 $multi-agent-iterate 继续这个运行目录里的任务。
读取 run.md 和现有产物，从未完成的步骤接着做。
```

更多场景见 [使用示例](references/examples.md)。只改名称、顺序或一句话时，直接修改并核验即可。

## 方法来源

借鉴 [pstack](https://github.com/backnotprop/pstack) 的独立候选、分工、质疑与验证方法，以及[这段视频](https://www.youtube.com/watch?v=NjoZoUm85x0)关于自主验证和减少重复人工纠正的思路。具体来源、时间点和适配差异记录在 [provenance.md](references/provenance.md)。

本 skill 独立编写，无需安装 pstack，也不绑定某个模型或业务系统。公司 OKR 是一个应用场景；有专门领域规则时，可结合对应 skill 使用，并避免重复启动两套迭代流程。
